# DOXA-SURE Brokerage Onboarding & Go-Live Checklist

## Gate 1 — Brokerage identity
- [ ] Legal entity name confirmed
- [ ] Trading name confirmed
- [ ] Company registration details recorded privately
- [ ] FSP number supplied
- [ ] FSP status checked against the FSCA source used for onboarding
- [ ] Key Individual / authorised decision-maker identified
- [ ] Compliance contact identified
- [ ] Complaints contact identified

## Gate 2 — Licence and service scope
- [ ] Relevant FSP categories/subcategories recorded
- [ ] Products/services the brokerage actually offers mapped
- [ ] Provinces/areas served recorded
- [ ] Customer types served recorded
- [ ] Insurer/product access declared
- [ ] Representative/adviser operating model confirmed
- [ ] Any services under supervision identified
- [ ] Any limitations/conditions recorded

**Hard stop:** No customer-facing “verified” status until this gate is completed.

## Gate 3 — Operating model
Choose one:
- [ ] Referral/technology partner only
- [ ] White-label technology partner
- [ ] Formal representative/juristic-representative structure (separate formal process required)

For the selected model:
- [ ] Roles and boundaries documented
- [ ] Customer handoff point documented
- [ ] Responsible FSP shown before regulated activity starts
- [ ] Advice/intermediary service ownership documented
- [ ] Record-keeping responsibility documented
- [ ] Complaints ownership matrix documented

## Gate 4 — Remuneration
- [ ] Platform plan selected
- [ ] Accepted-lead definition agreed
- [ ] Duplicate/test/invalid lead rules agreed
- [ ] Invoicing frequency agreed
- [ ] Any commission/revenue-share/financial-interest arrangement separately reviewed for compliance
- [ ] No routing preference purchased by a higher fee where eligibility is absent

## Gate 5 — POPIA / data security
- [ ] Minimum data fields agreed
- [ ] Purpose of each data transfer documented
- [ ] Responsible-party/operator roles considered and documented where applicable
- [ ] Data-sharing agreement signed before production transfer
- [ ] Retention/deletion rules agreed
- [ ] Security-incident contact and notification procedure agreed
- [ ] Customer rights/request process agreed
- [ ] Sensitive credentials expressly prohibited
- [ ] No sensitive customer files stored in public GitHub/public links

## Gate 6 — Customer-facing compliance
- [ ] Brokerage legal/trading name displayed correctly
- [ ] Correct FSP number displayed where appropriate
- [ ] Required disclosure wording approved
- [ ] Product/insurer wording approved
- [ ] Advice/quote journey starts only inside the brokerage's compliant process or another lawfully authorised structure
- [ ] “DOXA-SURE is an FSP” wording absent unless independently true
- [ ] No “use/borrow/rent our FSP licence” wording
- [ ] No guaranteed quote/claim/asset-rescue promises
- [ ] Debt counselling and legal representation kept outside FSP authority unless separately authorised by the relevant legal framework

## Gate 7 — Matching configuration
- [ ] Eligible service categories configured
- [ ] Geography configured
- [ ] Customer type configured
- [ ] Capacity/day configured
- [ ] Response-time target configured
- [ ] Excluded/out-of-scope services configured
- [ ] Paid plan cannot bypass eligibility rule
- [ ] Audit event recorded for every production match

## Gate 8 — Pilot activation
- [ ] MOU/commercial agreement signed
- [ ] Data-sharing/privacy terms signed
- [ ] Compliance sign-off obtained for the actual operating model
- [ ] Approved customer scripts loaded
- [ ] Approved disclosures loaded
- [ ] First pilot categories selected
- [ ] First pilot volume cap selected
- [ ] Test match completed with synthetic/demo data
- [ ] Two-user/tenant data-isolation tests passed before real customer records
- [ ] Escalation contacts tested

## Gate 9 — Controlled first-customer pilot
- [ ] First customer matched only to an eligible verified brokerage
- [ ] Customer shown responsible FSP identity
- [ ] Acceptance timestamp recorded
- [ ] Advice/quote process handled by responsible FSP
- [ ] Customer outcome/status tracked without DOXA-SURE implying responsibility for regulated advice
- [ ] Any complaint routed correctly
- [ ] Post-case audit completed

## Gate 10 — Expansion review
Review after the first 10–25 matched opportunities:
- [ ] Match acceptance rate
- [ ] Response time
- [ ] Out-of-scope lead rate
- [ ] Conversion rate
- [ ] Customer satisfaction
- [ ] Complaints/exceptions
- [ ] Data incidents
- [ ] Compliance exceptions
- [ ] Brokerage capacity
- [ ] Pricing sustainability

No national expansion until material compliance/security issues are resolved.

---

This checklist is an operational control document, not legal advice. The participating brokerage's Key Individual/compliance function and appropriately qualified South African legal/compliance professionals should confirm the final regulated operating model before production activation.
