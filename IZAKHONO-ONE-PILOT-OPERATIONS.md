# IZAKHONO ONE — Pilot Operations

## Operating objective

Convert a technically verified public pilot into repeatable product use without introducing behavioural tracking.

## Current CEO operating priorities

1. **First use beats infrastructure expansion.** The external ONE AI route remains the active public path while the owned R0 bridge is unresolved.
2. **No-account trial.** A visitor should be able to open ONE AI, load the Quick model and try a starter prompt before being asked to register.
3. **Mobile-first fast start.** Quick / SmolLM2 360M is the default tier. Balanced and Strong remain explicit user choices.
4. **No dead ends.** Browsers without usable WebGPU are routed to ONE Control and the Founding 1,000 rather than a blank or broken experience.
5. **Explicit feedback, not analytics.** Pilot feedback is submitted intentionally. The application does not send a browser fingerprint, referral ID, campaign ID or behavioural event stream.
6. **Measure only operating outcomes.** The scheduled Pilot Operations workflow records public health, aggregate Founding 1,000 registrations and aggregate feedback count.
7. **Keep the owned server route strategic, not blocking.** ISN-01 / another verified IZAKHONO sovereign node remains the intended server authority, but a queued self-hosted runner does not block public product learning.

## Conversion signals

- Founding 1,000 registrations
- explicit pilot feedback submissions
- public route health
- device-AI health
- owned bridge verification when available

The operating workflow deliberately does not collect page-view, clickstream, campaign, referral or user-level behavioural analytics.

## Escalation rule

If health is green and registrations remain at zero, do **not** add more infrastructure merely to create activity. Improve distribution, onboarding, value demonstration and direct customer outreach first.
